## 4. Gate 体系进化：BLOCK → REDIRECT → WARN 三级分化

### 基线状态（7/12）

第三轮设计定义了 PreActionGate（前置安全门），但所有门禁出口只有二分：PASS 或 BLOCK。

### 演进

经历三次迭代：

**第一次（7/25）：ADR-0012 REDIRECT**
在 oracle 判决中新增 REDIRECT 级别：
```
PASS → REDIRECT → FORCE/TRIGGER → ESCALATE → BLOCK
```
REDIRECT = 阻止 + 指引 + AI 自行修正重试，零人工介入。

**第二次（7/26）：五级谱系对齐（ai_self_decision.md 对齐）**
8f3f49a 将 5 个流程提示类的 REDIRECT（plan_missing / current_step_missing / cd_churn / multi_cmd_newline / redundant_file_probe / dialogue_residue）降级为 WARN。
理由（ai_self_decision.md Rule 2）：这些属于"行为指导"和"流程提示"，非安全/越权场景，不应打断 AI 工作流。
保持 REDIRECT 的：gov_file_bypass（越权）、reviews（越权）、task_blocked（状态锁）、terminal_inertia（劫持防护）、verify-gate（E3 虚假完成靶心）。

**注意**: 7/26 的 REDIRECT 此时还只是"拦截+一句话提示"，没有选项指引。7/27 REDIRECT 升级为完整软打断（三选项+三次上限）后，这 5 个流程提示是否应回到 REDIRECT 尚未评估。

edit-scope 越界从 BLOCK 降为 WARN（在 54d0da0 完成）。

**第三次（7/27）：分级语义收敛——本日**
最终形成：

```
三种出口模式：
  WARN      — 写入后提醒（已存在且关联 的操作不可撤销时使用，仅PostToolUse）
  REDIRECT  — 写入前拦截 + 三选项指引（可修复的非高险违规，3次后→BLOCK）
  BLOCK     — 写入前硬阻断（不可逆/越权/架构风险，无绕过路径）

Gate 9: 数值断言溯源  (L2)
  WARN → REDIRECT 升级
  检测无来源数值断言 → 选项A(补来源)/B(删断言)/C(重复拦截)
  检测内容：提升/下降/通过率/倍率/比较公式

Gate 10: 文件引用溯源 (L1+L2)
  新增 Gate，基于 read-tracker 交叉验证 file:line 引用
  支持 backtick/裸引用/Markdown/大写扩展名
  豁免路径：.claude/references/、test-/tests/

三次上限机制：
  同一 Gate 连续 REDIRECT 3次 → 升级 BLOCK
  计数器 v2 格式（含时间戳），6h TTL 跨会话过期
```

→ 详见 `redirect-mechanism.md`、`pretool-gate.py`、`anti-patterns.md K1/K2/K3`

## 5. trust_breach 信任破裂机制

### 基线状态（7/12）

无信任破裂概念。任何违规都是单次处理，不影响后续操作。

### 演进

7/26 新增（来自 Opus 5 启发）：

```python
# 一条恶意行为（env_bypass / temp_bypass / self_mint）后：
写 .omc/state/trust-breach.json
→ 所有后续工具调用直接 BLOCK（不经过正常 gate 判决链）
→ archive 时自动清除标记
```

设计原则：
- 一次严重违规后所有后续请求进入警戒态（零信任）
- 不是永久封禁，archive（人工确认任务结束）自动清除
- 当前在 carros_base.py archive 路径中清除

→ 详见 `pretool-gate.py _check_trust_breach()`、`test-7-fixes.py trust_breach 测试`
