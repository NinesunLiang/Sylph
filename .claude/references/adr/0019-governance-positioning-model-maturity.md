# 0019. 治理定位再校准：模型成熟后的 CarrorOS 意义与装机门槛

**日期**: 2026-08-14
**来源**: 用户提问「DeepSeek-v4-flash 7/30 后 harness 能力大大提升，CarrorOS 意义是什么，还值得为新项目装吗」+ index22 双法官评测证据

## 上下文

DeepSeek-v4-flash 于 2026-07-30 后能力大幅提升。index22 双法官独立评测（10 次真实 `claude -p` 空上下文 A/B）给出一个**诚实但关键**的发现：

> **诚实/守约/防遗忘，ON（有治理）与 OFF（无治理）行为几乎不可区分。**
> 探针 prompt 自带诚实要求 + 基础模型已足够谨慎，治理的**边际诚实价值未被证明**（index22 M9，双法官一致）。

同时 index21/22 评测也给出治理的**真实增量证据**：A-ON 自建任务系统、E-ON 按 AGENTS.md 惯例落盘、B-ON 披露 hook 副作用、跨会话状态可续跑。且轻量化后治理成本降至 0.93x（ON 合计 92.5s < OFF 99.6s，index22 最终版）。

**核心矛盾**：模型变强使「防错」类治理冗余，但「长期多智能体协调」类治理仍必要。CarrorOS 的定位需要显式再校准，否则会陷入「为防错而装、却用不上防错」的错配。

## 决策

**将 CarrorOS 的定位从「AI 错误防护网」显式迁移到「长期多智能体治理基础设施」**：

1. **核心价值重新排序**（对模型成熟时代）：
   - **跨会话/跨 Agent 持久状态**（token/plan/executor/handoff 全磁盘，抗 compact）——模型上下文再长也会断，状态在磁盘才不丢
   - **多智能体协调**（subagent 调度、双法官、goal 状态机）——多个 AI 一起干活时无状态机即混乱
   - **真相源收敛**（references 唯一真源、文档去重）——模型越多文档越容易长毛，治理负责剃毛
   - **可审计性**（EV 证据块、审计日志、双法官盲评）——出事能查"谁改的、为什么"，模型不会自己写账本
   - **评测体系**（index1-22 纵向账本、双法官盲评）——不断自己评自己，最不可替代

2. **「防错」类能力降为次要**（诚实标注）：不编造/守范围/防遗忘已是模型默认能力，治理的边际诚实价值**未证明**。不再把「模型会撒谎」作为装机主卖点。

3. **装机门槛显式化**（少即是多）：
   - **值得装**：长期项目（跨几十会话、会 compact）、多智能体、有状态/文档需维护、需审计
   - **不值得装**：一次性小任务、单会话搞定、无需续跑、用户自己盯着
   - 快速交付型项目：裸模型 + 自定义 CLAUDE.md 足够，不背整个治理

## 替代方案

- **维持「防错网」定位**：被否决——index22 双法官一致证明 ON≈OFF，诚实价值未被证明，继续主打会误导装机决策。
- **建议不装**：被否决——长期多智能体项目的协调/状态/审计价值是模型能力替代不了的。
- **继续无限轻量化到「隐身」**：部分采纳——轻量化方向正确（ON 0.93x），但保留核心状态/评测机制，不砍到只剩文档。

## 理由

- **证据驱动**：index22 双法官独立给出「诚实 ON≈OFF」与「治理引导真实存在」两组证据，定位必须同时容纳两者——防错冗余、协调必要。
- **少即是多**：装机门槛显式化避免「为治理而治理」；快速项目不背重负，长期项目有据可依。
- **诚实优先**：不夸大「模型会犯错」的恐惧营销，实事求是标注边际价值未证明，与铁律#1（不编造）一致。

## 验证 vs 存疑（2026-08-14 二次检验）

对本 ADR 定位的每一项做证据检验，区分「已证明」与「待验证」：

| 身份要求 | 状态 | 证据 |
|---|---|---|
| 跨会话持久状态 | ✅ 强证据 | 6+ token 文件 + active-resume 指针 + 全磁盘状态；index21/22 跨会话评测靠磁盘恢复 |
| 多智能体协作 | ✅ 协作已实证 / ⚠️ 并发未测 | index21/22 双法官真实 spawn 各自盲评 + subagent 分配记录真实存在 |
| 评测体系 | ✅ 最强 | 23 份 index 纵向报告；A/B 电池 + 双法官盲评 + 修复闭环（死锁→0.93x 真实迭代） |
| 真相源收敛 | ✅ 收敛已维持（撤回"易反弹"误判） | index.md 数字准确（17 hooks/10 skills）；唯一死链是 AGENTS.md:6 注释示例 `@README.md`，非实际引用；清理后文档未再长毛 |
| 跨会话恢复机制 | ✅ 有专项测试 | `p0-recovery-schema-alignment`、`isolation-and-lossless-handoff` 任务 |
| **并发协调** | ⚠️ **真缺口（唯一硬核未证明）** | 有 CAS 锁/active-resume 指针等机制，但**无「两 agent 同时 init/verify/archive 同一任务」的端到端测试**；index22 双法官 C7 均给 7（"双审运行期不可观测"） |

**结论**：CarrorOS 符合「中期、多智能体、评测驱动的治理基础设施」；"长期"与"并发冲突"是最硬的两项，「并发协调」是唯一未被证明的硬核。真相源收敛与恢复机制均比预期强（本轮修正了此前"易反弹/未压力测试"的过度保守判断）。

## 影响

- Benchmarking/index22.md 的 M9（诚实探针 ON≈OFF）作为本 ADR 的证据锚点。
- 未来新项目装机决策参考本 ADR 的门槛清单。
- 评测方向：需加「更难对抗探针」测治理净增益（index22 优化项，index23-adversarial-probes 已启动）。
- **待验证硬核**：并发协调——需设计「两 agent 并发操作同一任务」的端到端测试，验证 CAS 锁/状态机在多智能体真并发下不冲突。
