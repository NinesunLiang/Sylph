# 0017. 文档真源收敛：references/ 唯一 + 大编号优先

**日期**: 2026-08-13
**来源**: 独立评估-index16 后用户指令（"所有文档收到 .claude/references/ 下一处，去重去过时，一份唯一反映现实的文档"）

## 上下文

CarrorOS 文档散布多处且历史迭代严重：

- `references/design-docs/` 有 21 个文件，其中 1~11 是第三轮迭代设计（2026-07-12 冻结）、12 是设计演进、align/data_todo/update/总结 是过程记录——**绝大多数是历史草稿，不反映当前状态**，仅 13-headless-lightweight-actions.md 是活文档；
- 多处文档内容过时（feature-registry 曾写"统一 14 门"，实为 L1 5 道/L2 15 道；index.md 曾写"G1-G6"）；
- 同一主题存在多版本（design-docs 编号 1-13 与 adr 0016 等可能描述同一决策的不同阶段）；
- 无统一"哪份是唯一真源"的覆盖规则，未来 reader 无法判断冲突时信谁。

用户要求：**所有文档收敛到 `.claude/references/` 下一处，去重去过时，就一份唯一反映现实的文档；以后有调整就在这个文档集合上继续覆盖；冲突时大编号优先（如 19.md > 17.md）**。

## 决策

1. **`.claude/references/` 是文档唯一真源集合**——所有活跃设计/决策/规则文档收敛于此，其他位置（design-docs、nodes、workflows 等）不得再作为"当前状态"的独立真源。

2. **编号文档（design-docs/*.md）采用"大编号优先"覆盖规则**：
   - 同主题冲突时，大编号文档覆盖小编号文档（如 19.md > 17.md）；
   - 编号文档只增不改（新增设计 = 新编号），历史编号保留为演进记录但**不再反映当前状态**；
   - 当前状态的唯一真源 = 该主题的最大编号文档 + 对应 ADR。

3. **历史迭代文档归档**：design-docs 1~11（第三轮迭代冻结）、12（演进）、align/data_todo/update/总结（过程记录）移入 `references/archived/`，不删除（git 可恢复），但 INDEX 标注"历史存档，不反映当前状态"。

4. **去重去过时**：同主题多版本收敛到一份；过时描述（如"14 门"）更新为当前真相；ARCHIVED 目录不参与默认上下文。

## 替代方案

- **不收敛**：维持现状，各目录各自演进 → 文档蔓延加剧，冲突无规则，策略易回退（被否——正是用户要解决的）；
- **全删历史**：design-docs 1-11 直接删除 → 丢失演进记录，git 虽可恢复但破坏文档考古（被否——归档优于删除）；
- **仅改索引**：不归档只改 design-docs/INDEX 标注 → 历史草稿仍在活跃目录，未来 reader 易误读（被否——需物理隔离）。

## 理由

- 单一真源（ADR0015 契约收敛同哲学）避免"多版本并存、冲突无规则"；
- 大编号优先提供明确的覆盖语义：未来新增设计只需递增编号，读者按最大编号取当前状态；
- 归档而非删除保留演进历史，且物理隔离（archived/）避免误读；
- index16 实证过时文档会误导（G1-G6/14门），收敛是防策略回退的文档层保障。

## 后果

- **正向**：references/ 成为唯一可信任的当前状态源；冲突有明确覆盖规则（大编号优先）；历史文档物理隔离；
- **约束**：新增设计必须走 references/ 收敛路径（新编号 + INDEX 更新），禁止在别处另起真源；
- **风险**：收敛过程（归档/合并）涉及大量文件移动，需分批执行 + git 可恢复；
- **兼容**：ADR0016 已固化的策略在 references/ 下，与本文档规则一致。
