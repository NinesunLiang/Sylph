## 一、哲学定位

门禁出口等级谱系（从轻到重）:

```
  PASS → NARROW → REDIRECT → ESCALATE → BLOCK → HARD_BLOCK
  通过    提鞋     打断升级    人类裁决   物理阻断   不可逆阻断

  ↑ REDIRECT 在此              ↑ BLOCK 在此
  软打断: 给你选项             硬打断: 没得商量
  "停下来看看"                "不许动"
  安全非高险场景               高险/不可逆/越权/架构
```

哲学映射:

| 原则 | 体现 |
|------|------|
| #4 验证 | 每次引用和断言必须可追溯 |
| #6 零信任 | 门禁机械扫描，不信任AI自觉 |
| #3 守护 | 阻止事实错误写入文件 |
| #5 人本 | 给出选项，不替AI做决策 |
| #2 增益 | 低于BLOCK的摩擦力，高于WARN的强制力 |
| #1 少 | 不新增hook文件，增强已有gate |

## 二、三种交互模式对比

| 维度 | WARN (旧) | REDIRECT (新) | BLOCK (已有) |
|------|-----------|---------------|--------------|
| 触发时机 | 操作已执行 | 操作未执行 | 操作未执行 |
| 能否继续 | 能（无人管） | 修正后重试 | 不能 |
| 物理强制力 | 0 | continue=False | continue=False |
| 适用场景 | 需了解但非紧急 | 可修复违规 | 危险/不可逆 |
| 反复不改 | 每次WARN | 3次后→BLOCK | 永远BLOCK |
| 是否告知下一步 | 否 | 选项A/B/C | 给建议 |
| AI自主权 | 完整 | 有，AB都可 | 无 |

## 三、选项三件套格式

每条 REDIRECT 统一结构:

```
⛔ 原因: [具体违规描述]
     [哲学/铁律引用]

✅ 选项 A —— [推荐修复方式]（推荐）:
    [具体操作步骤]
    → 结果: 操作通过

⏭️  选项 B —— [替代修复方式]:
    [具体操作步骤]
    → 结果: 操作通过，[附带影响]

⏹️  选项 C —— 维持原内容重试:
    → 结果: 操作被重复拦截（直到选择A或B）
```

设计规则:

1. 选项 A 永远是推荐路径（最高质量结果）
2. 选项 B 是退而求其次（通过但略降质量）
3. 选项 C 是维持+重复拦截（不允许跳过）
4. 每个选项必须附带"结果"（AI看到决策后果）
5. 不要求AI选A——B也是合法通过路径

## 四、注册 Gate

### Gate 9: `_check_numeric_claim` — 数值断言溯源

**位置**: pretool-gate.py 约 L1710

**触发条件**: 写入 `.md/.rst/.txt/.json/.yaml` 文件中包含无来源的数值断言

检测模式:

- 提升/下降类: "性能提升了30%"
- 性能指标类: "覆盖率提升20%"
- 通过率/成功率: "准确率达99.7%"
- 比较类: "从60%提升到85%"
- 倍率类: "3倍性能提升"

豁免模式:

- 操作计数: "修复了5个bug", "增加了10个测试文件"
- 步骤计数: "第3步", "共5个文件"
- semver版本号: "1.2.3-beta"
- 端口号: "port 8080"
- HTTP状态码: "HTTP 200"
- 代码行数: "代码行数42"

来源检查: 对每个匹配的数值断言，在内容中 ±200 字符窗口内搜索来源引用标记

REDIRECT 输出:

```
⛔ 原因: 写入内容包含无来源的数值断言
    铁律#1(不编造)要求: 每项数值必须有可验证来源引用。

✅ 选项 A —— 补充来源标注后重试（推荐）:
    引用Read过的文件: `[[已验证:文件名:行号]]`
    引用实测数据: `[来源:命令 exit_code]`
    内部估算: `[内部自检，非行业标准]` 并附推算依据
    → 结果: 操作通过

⏭️  选项 B —— 直接移除无来源的数值断言:
    → 结果: 操作通过，不写入断言

⏹️  选项 C —— 维持原内容重试:
    → 结果: 被重复拦截
```

**评级**: L2（完整模式）

### Gate 10: `_check_claim_source` — 文件引用溯源

**位置**: pretool-gate.py 约 L1766

**触发条件**: 写入任何文件时，内容中包含 backtick-enclosed `file.ext:line` 引用

检测正则: `` `([a-zA-Z0-9_./-]+\.[a-z]+:\d+(?:-\d+)?)` ``

豁免路径:

- `.claude/references/`（文档中的模式说明示例）
- `test-` / `tests/test-`（测试中的引用不是断言）

机械检查流程:

```
1. 提取所有 backtick 内 file:line
2. 读取 read-tracker.txt（本会话已读文件）
3. 对每个引用: 完整路径或 basename 是否在 tracker 中
4. 有未读项 → REDIRECT
5. read-tracker 不存在（冷启动）→ 跳过，记录 audit
```

REDIRECT 输出:

```
⛔ 原因: 写入内容引用了未在本会话Read过的文件
    铁律#1要求: 引用file:line前必须先Read

✅ 选项 A —— 先Read再重试（推荐）:
    Read后文件自动进入tracker，重试即通过
    → 结果: 操作通过

⏭️  选项 B —— 移除未读文件引用:
    删除引用后重试
    → 结果: 操作通过

⏹️  选项 C —— 维持原内容重试:
    → 结果: 被重复拦截
```

**评级**: L1（轻量模式也注册——铁律#1底线）

## 五、三次上限升级

所有 REDIRECT gate 统一实现于 pretool-gate.py `main()` 入口:

行为矩阵:

| 次数 | 行为 | AI感受 |
|:----:|------|--------|
| 第1次 | REDIRECT | 原因+选项，修正后重试 |
| 第2次 | REDIRECT | 同上，仍未修正 |
| 第3次 | BLOCK | 放弃当前方向 |

跨会话: 计数器持久化到 `redirect-streak.json`（v2 格式: `{"gate": {"c": count, "t": timestamp}}`）。6h TTL 过期重置，v1 格式（旧会话遗留）自动清零。
