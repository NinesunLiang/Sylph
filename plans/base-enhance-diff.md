# CarrorOS Base 与 Enhance 核心差异

> 记录于 2026-07-22，Boss 确认

## 本源

- **同源、同价值观**：两个项目共享一套哲学体系（验证 > 零信任 > 守护 > 文档 > 人本 > 增益 > 少）
- **分层的根本原因**：不同能力的模型在同一套治理体系下表现天差地别

## 定位

| 维度 | Base | Enhance |
|:----|:----|:--------|
| **目标模型** | 中低阶模型（DeepSeek-V4-Flash、Qwen3.7-Plus 等） | 高阶模型（Opus、GPT、Grok 等） |
| **核心理念** | 路径正确 → 约束模型行为 | 路径正确（Base基础）+ 增强 |
| **实现方式** | superpowers 式严格路由 + spec 规格文档导航 | grill-me 式充分调研 + TDD 验收（不设 spec 文档限制能力发挥） |
| **不适配** | 飞轮系统等需高模型能力的功能 | — |

## 共同目标

1. 可靠性
2. 诚实性
3. 安全性
4. 能力上限

## Enhance 独有目标：AI 资产化

Enhance 多一个目标：**让 AI 越来越懂你、越来越聪明、越来越懂项目，成为持续增值的资产。**

实现路径：`.claude/claude-next.md` → `.error-dna` → `anti-patterns` → **数据下沉** → **升华机制**

## 决策原则

一个治理能力放 Base 还是 Enhance？
- **Base**：在该能力上中低阶模型能起到效果 → 放 Base，为基础版本
- **Enhance**：在 Base 基础之上增强；若能力不适合 Base（中低阶模型不足以起到效果）→ 仅放 Enhance
- 同一个能力可以在两套模型上各有一套实现（Base 版本 + Enhance 增强版）
