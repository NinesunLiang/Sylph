# 内部工程原则（Goal / RPE 按需使用）

只在对应问题出现时加载，不建立额外流程或入口。

## 设计与可测试性
- 优先小接口承载完整行为，隐藏复杂性；接口说明约束、错误和调用顺序。
- 删除模块后，复杂度是消失还是散到调用方？无真实变体不新增抽象层。
- 依赖从边界传入，计算优先返回结果，副作用集中；测试通过公共接口验证行为。

## 反复失败的根因分析
- 先保存复现命令、实际输出、预期差异，再追到最早出现分歧的状态或数据边界。
- 每层原因须有代码或运行证据；用反例推翻假设，不能靠重复重试证明。
- 修复产生问题的机制边界，先红后绿；补相关回归，记录未验证部分。
- 证据不足时继续调查；涉及人类裁决的边界不由模型评分代替。

## 术语一致性
仅在一词多义、多词一义、与既有领域定义冲突时指出歧义。
沿用项目术语；不为统一措辞擅改宪法，不新增术语管理流程。

## 任务分拣
小修按 AGENTS 的 L1 路径；跨模块等 L2 条件走完整文档与验证。
无人目标使用 Goal，人机协作特性使用 RPE；每步按依赖执行并留证，不叠加第二套卡片状态机。
