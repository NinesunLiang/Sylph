# CarrorOS Delivery

**给 AI 一个目标，它自己跑完，交你一份带证据的交付报告。**

交付版（Delivery Edition）只做一件事，把这件事做到底：
你写清目标 → AI 问清一次 → 无人值守执行 → 交付代码 **+ 一份可以直接给客户的报告**。

> ### 四个卖点，每条都拿得出证据
>
> **过程可观测 · 安全 · 敢让客户离开后持续工作一天 · 回来还有掌控感**

---

## 卖点拆解：客户真正怕什么，我们拿什么回答

| 卖点 | 客户心里的那句话 | 机制 | **你能当场拿出的证据** |
|---|---|---|---|
| **过程可观测** | "它在里面到底干了什么？" | 每步写证据块（改了哪个文件、断言了什么、退出码）+ 每次门禁判定写 JSONL 审计 | `.omc/audit/*.jsonl`、任务目录 `evidence.jsonl`、报告第二节 |
| **安全** | "会不会把我的密钥、数据库、线上环境搞坏？" | 14 道运行时门禁：密钥/凭据、敏感路径、危险命令、治理文件自改、sudo、force-push、未验证就宣称完成 | 门禁拦截记录（可现场演示：让 AI 写一个密钥 → 被拦下） |
| **敢离开一天** | "我不在的时候它卡住了、跑偏了怎么办？" | 前置澄清一次问清 → 执行期不暂停/不提问/不中断 → 卡点按决策链自决 → 真正的硬边界记进"需你决定"表 | 退出报告第四节：**每件事为什么需要你定 + AI 的建议 + 依据** |
| **回来有掌控感** | "回来要花两小时搞清楚到底发生了什么" | 退出报告（内部版给真相，客户版给人话）+ handoff 恢复 + 状态全落磁盘 | `交付报告.md` 一份，七节看完就知道验收还是不验收 |

**这四条不是营销词，是四份可以给客户看的文件。** 竞品里：
纯自主 agent 能给"跑完了"，给不出"为什么这三件事我不该自己决定"；
纯检查工具能给"拦住了"，给不出"我替你把活干完了"。

## 一行命令装进你现有的项目

```bash
# 1) 下载单个脚本（604 KB，自解压，无需 clone 仓库）
curl -fsSL https://raw.githubusercontent.com/NinesunLiang/Sylph/main/packaging/products/carroros-delivery/dist/carroros-delivery-install.sh \
  -o carroros-delivery-install.sh

# 2) 装进你的项目
bash carroros-delivery-install.sh /path/to/your-project
```

装完自检：

```bash
cd /path/to/your-project && python3 .claude/scripts/carros_base.py status
```

> 为什么不用 `curl | bash`：自解压包需要读到自己的文件体，管道执行拿不到
> （脚本会直接提示你改成两步）。两步还有个好处——**你可以先读一遍脚本再跑**。

**不会动你的代码、不改你的依赖**，只在 `.gitignore` 追加两行（`.claude`、`.omc`）。

### 安装器做了什么（不黑箱）

1. 解包自身（tar.gz + base64，单文件自解压）到临时目录
2. 复制 `.claude/` 治理层 + `AGENTS.md` / `CLAUDE.md` / `README.md` / `LICENSE`
   —— 目标已有同名文件时**另存为 `.carroros-new`，不覆盖**
3. 建 `.omc/{state,tasks,tokens,audit}` 空骨架（不写任何数据）
4. `.gitignore` 幂等追加 `.claude` / `.omc`
5. 自检五大系统文件是否齐备

> Windows 原生不支持（治理代码依赖 `fcntl` 文件锁）；WSL / macOS / Linux 可用。

## 它装了什么（五套系统，其余一概不装）

| # | 系统 | 作用 | 关键文件 |
|---|------|------|---------|
| ① | **lx-goal 目标模式** | 一次前置澄清 → 全自动执行 → 退出报告 | `.claude/skills/lx-goal/` |
| ② | **文档系统** | 任务文档（research/plan/executor）+ 进度 + 归档 | `.claude/scripts/carros_base.py` |
| ③ | **令牌系统** | `.omc/tokens` 带 CAS 的状态源（并发写保护） | `.claude/scripts/token_lifecycle.py` |
| ④ | **抗 compact** | 状态全落磁盘；对话被压缩/换会话后仍能续跑 | `handoff` + `resume` 链路 |
| ⑤ | **hooks 门禁** | 14 道运行时门禁，fail-closed，全程审计 | `.claude/hooks/` |

不装：其它 11 个技能、示例应用、内部评测、历史归档、运行时数据。

## 用起来是这样

```
你：/lx-goal 把官网首页改成响应式，手机端 375px 宽不能出现横向滚动条
AI：（Phase 0，一次问清）——主图用哪张？旧页面要一起改吗？
你：（回答完就走开）
AI：（无人值守执行：改代码 → 跑测试 → 写证据 → 归档）
你：（回来）看报告
```

出报告：

```bash
# 内部版（机器真相源，含 verdict、证据索引）
python3 .claude/scripts/carros_base.py status
python3 .claude/skills/lx-goal/scripts/lx-goal.py report

# 客户版（可直接发给付费方的那一份）
python3 .claude/skills/lx-goal/scripts/lx-goal.py report --format client --out 交付报告.md
```

客户版七节，没有一个治理术语：

| 节 | 内容 |
|---|------|
| 一、结论 | 建议验收 / 建议暂缓验收 + 数量表 |
| 二、本次交付内容 | 交付项 / 状态 / 验证情况 |
| 三、这些内容是怎么验证的 | 先测试后实现、行为受约束、全过程可追溯 |
| 四、**需要你决定的事** | 事项 / 为什么要你定 / **我的建议 + 依据** |
| 五、本次未做的部分 | 范围排除项 + 原因 |
| 六、需管理员权限执行的操作 | 硬边界操作清单 |
| 七、验收方式 | 如何逐项验收 |

第四部分是这套东西最难被替代的地方：**AI 主动承认"这几件事我不该自己决定"**，
并给出推荐方案和依据。纯自主 agent 给不出这个，因为它不承认自己不确定。

## 它凭什么敢无人值守

| 机制 | 具体做法 |
|---|---|
| **前置澄清** | Phase 0 一次只问一个问题，能自答的不问你；AI 自判 L1/L2，不用你记参数 |
| **证据门禁** | 没写证据的完成不算完成；声称完成但没跑验证 → 被拒 |
| **敏感操作拦截** | 密钥/凭据写入、敏感路径、危险命令、治理文件自改、`sudo`、`force-push` 全部走门禁。**默认交互模式必须你点头才放行**；若开启自动放行，这些门退化为"拦截 + 留痕"并写审计（报告里可查） |
| **崩溃即拒绝** | 安全门自身出错时**拒绝执行**，而不是静默放行（fail-closed） |
| **状态落磁盘** | 对话压缩、换会话、关机器，任务都能续上 |
| **隔离执行** | L2 任务在 worktree 里跑，改不到你的主工作区（由门禁强制） |
| **全程审计** | 每次拦截、每次审批、每次跳过都留 JSONL 记录 |

---

## 它不做什么（避免误期待）

- **不判断业务逻辑对不对** — 它管得住 AI 的**行为**，管不住 AI 的**判断**。业务正确性靠测试和你的验收。
- **不保证零事故** — 是「减少翻车 + 留下可审计记录」，不是消灭风险。
- **不提升模型智商** — 不会让弱模型变强，只会让任何模型更守规矩。
- 目前 macOS / Linux / WSL；Windows 原生不支持（依赖 `fcntl` 文件锁）。

## 目录结构

```
.claude/
├── skills/lx-goal/      # ① 目标模式（SKILL.md + references + lx-goal.py）
├── scripts/             # ②③④ 文档/令牌/抗compact 引擎
├── hooks/               # ⑤ 门禁（pretool-gate + 14 门 + 审计）
├── nodes/ schemas/ rules/   # AI 行为节点与契约（指令层）
├── kernel.md index.md   # 管理内核 + 渐进式披露路由
└── settings.json        # hook 接线（装完即生效）
.omc/                    # 运行时状态：tokens / tasks / audit / state（不入库）
AGENTS.md                # 宪法：哲学裁决链 + 铁律 + 工作流
```

## 想要完整版 CarrorOS

交付版刻意做小：**只有 lx-goal 一个技能、14 道门禁**。完整版在此基础上多出：

| 完整版多什么 | 具体 |
|---|---|
| **12 个技能** | 需求拆解 / 领域建模 / 代码库设计 / 根因分析 / 提交前检查 / 推送前检查 / 步骤化执行 / 任务规格 / Oracle 评审 / 目标模式 / RPE / 评审复核 |
| **25 道门禁** | 交付版 14 道之外，增加评分卡门、工作集门、知识注入、夜间模式、声明审计等 |
| **双法官验收** | 高风险任务由两个独立判官盲评，输出裁决与理由 |
| **学习飞轮** | `error-dna` 错误 DNA 库：同一个错误不再犯第三次 |
| **发行链** | 可把治理层再打包分发给你的客户（本产品就是它的子集） |

**仓库**：<https://github.com/NinesunLiang/Sylph>
**完整安装**（全量治理包）：

```bash
git clone https://github.com/NinesunLiang/Sylph
bash Sylph/packaging/install.sh /path/to/your-project
```

> 建议路径：**先用交付版跑通一单**（有报告、能验收），确认这套流程适合你，再上完整版。
> 反过来（一上来装 25 道门 + 12 个技能）大多数人会在第一天被门槛劝退。
