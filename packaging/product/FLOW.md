# 使用说明

> 你刚把它装进项目。这份文档告诉你：**怎么发起任务、中途会发生什么、回来怎么验收、出问题怎么办。**
> 所有命令都在项目根目录执行，可直接复制。

---

## 1. 30 秒上手

```bash
# ① 确认装好了（应输出 "No active task"）
python3 .claude/scripts/carros_base.py status

# ② 对 AI 说这句话（在 Claude Code 等 AI 编程工具里）
/lx-goal 把官网首页改成响应式，手机 375px 宽不能出现横向滚动条
```

然后：**AI 会问你几个问题 → 你答完 → 你去干别的 → 回来收报告。**

不用记任何参数。级别（L1/L2）它自己判断，你只说要做什么。

---

## 2. 开始之前，确认三件事

| 检查 | 怎么做 | 为什么 |
|---|---|---|
| 项目用 git 管着 | `git status` 能正常输出 | L2 任务要在独立分支上干活，没 git 就没有隔离 |
| 工作区是干净的 | `git status` 没有未提交改动 | 否则它分不清哪些改动是它做的 |
| Python 3 可用 | `python3 -V` | 治理层是 Python 写的 |

第三条不满足就别装了；前两条不满足，先提交一下再开始。

---

## 3. 发起一个目标：目标怎么写

**好目标**长这样（三要素：要做什么 + 做到什么程度 + 什么不能碰）：

```
/lx-goal 给管理后台加导出功能，支持 Excel 和 CSV，
         导出 5 万行以内不许卡超过 3 秒，
         不要动现有的权限模块
```

**坏目标**长这样，会被反复追问：

```
/lx-goal 优化一下后台
```

> 判断标准：**你能验收吗？** 你说不出"怎么算做完了"，它就只能在澄清阶段一直问你。

目标写好了，其它都交给它。你不需要指定 L1/L2、不需要写计划、不需要拆步骤。

---

## 4. AI 会问你一次，之后不再问

发起后它进入**澄清阶段**——这是唯一需要你的阶段。规则：

- **一次只问一个问题**（不是甩给你十个问题让你填表）
- **能自己查的不问你**（先读代码和文档）
- 你答完，它会重新看还有没有要问的，没有就开工

几点实用建议：

| 情况 | 你可以这样说 |
|---|---|
| 你也不确定 | 「你决定，按你判断做」——它会自己拍板并写进报告 |
| 问题问偏了 | 「这个不重要，重点是 ___」 |
| 想改范围 | 直接说，澄清阶段改范围是免费的 |
| 想先看方案 | 「先说方案，别动手」 |

澄清结束它会给一份执行计划给你确认，**确认后你就自由了**。

## 5. 它开工之后，你的项目会发生什么

### 5.1 会新增这些（都在 `.omc/` 里，不进 git）

```
.omc/
├── tasks/<日期>/<任务名>/      ← 这个任务的"工作档案"
│   ├── research.md            它查到的现状和约束
│   ├── plan.md                要做哪几步、每步怎么算验收通过
│   ├── executor.md            实际做了什么（每步附证据）
│   ├── handoff.md             做到哪了（换会话靠它接上）
│   └── state/goal-report.md   报告（§7）
├── tokens/<日期>/<任务名>.json  状态存档
├── audit/<日期>.jsonl          它被拦下的每一次操作
└── state/active-resume.json    "当前任务是哪个"
```

你的源码、`package.json`、`requirements.txt`——**一个都不动**。
装的时候只在 `.gitignore` 加了两行（`.claude`、`.omc`）。

### 5.2 你的任务有一个固定地址

每个任务都有一个可用一辈子的地址：

```
.omc/tasks/20261027/官网改版-4be89f5b
```

三件实用的事：

1. **可以存下来**。贴到工单、微信、客户群里都行；一个月后拿这个地址还能查到当时的完整档案。
2. **归档后地址依然有效**。任务做完归档了，内容搬到 `.omc/archive/`，但原地址仍然能打开（它会自动跳过去）。所以你不会遇到"链接失效、档案找不到了"。
3. **任务名可以写中文**。允许中文、字母、数字和 `. _ -`，最长 200 字。不能带 `/` 或以 `.` 开头——这是防止文件写到你项目外面去。

查当前任务：

```bash
python3 .claude/skills/lx-goal/scripts/lx-goal.py status
```

### 5.3 L2 任务（大任务）在独立分支上干活

如果它判断这是个**大活**（跨模块、不可逆、碰安全权限、改动面大），会这样做：

1. 新建一条 git 分支，名字以 `task-isolated-` 开头
2. **所有代码改动只发生在这条分支里**，你的主分支在它干活期间保持干净
3. 如果它（或它的子任务）试图改主工作区，会被直接拦下，并被告知去改分支里的对应文件
4. 干完、测试全绿之后，改动**合回你发起任务时所在的分支**，然后删掉临时分支

**你可以自己验证**：

```bash
git branch -a          # 干活期间能看到 task-isolated-* 分支
git log --oneline -5   # 收尾后能看到合并记录
```

**这条机制的实际价值**：你可以对客户说"这次改动的全部代码都在一条独立分支里，执行期间不允许直接改主分支，最后合并——分支记录你可以自己查"。这句话是可验证的，不是形容词。

> 小任务（L1）不开分支。单文件小改开分支反而是负担。

## 6. 你能离开多久

**默认 6 小时**（可以在发起时调：`/lx-goal <目标> 12` 表示 12 小时）。

期间它不会停下来问你。遇到问题的处理方式：

| 它遇到什么 | 它怎么做 | 你要做什么 |
|---|---|---|
| 有歧义、有多种合理做法 | 自己按项目现状拍板，**在报告里标注"这是我的判断，理由是…"** | 回来复核这条判断 |
| 需要你的业务决策（比如用哪张主图） | 记进报告的"需要你决定"表，**继续做其它能做的部分** | 回来一次性回答 |
| 需要你亲自执行的操作（跑生产 SQL、改线上配置） | 记进报告，**不擅自执行** | 回来自己执行 |
| 卡住了、试了三种办法都不行 | 记为"阻断项"，继续下一项 | 回来决定是否放弃这一项 |
| 快到时间了还没做完 | 只要还在推进，自动续一段时间 | 不用管，第二天看报告 |

**核心原则**：它不会为了一个卡点停下整条流水线，也不会替你决定那些只该你决定的事。

## 7. 回来怎么验收（三步，5 分钟）

### 第一步：看结论

```bash
python3 .claude/skills/lx-goal/scripts/lx-goal.py report
```

报告开头有一行结论，只有两种：

- **建议验收**：计划内的事全做完且都有验证证据
- **建议暂缓验收**：还有没做完或没证据的项（下面会列出来是哪些）

### 第二步：只看「需要你决定的事」那张表

这是整份报告里最该看的部分，长这样：

| # | 事项 | 为什么需要你定 | 我的建议 |
|---|---|---|---|
| 1 | 首页主图用哪张 | 需要你的业务判断 | 建议第二张（移动端留白更舒适） |
| 2 | 老页面 SEO 兼容改造 | 本次未纳入，需你确认是否追加 | 建议评估后决定（老页面收录暂不变） |

**每一项都带它的建议和理由**——你不用从零想，只需要点头或换一个。

### 第三步：扫一眼「本次未做」

确认没有你以为做了但其实没做的东西。范围排除项都在这。

## 8. 给客户的交付报告（这是你收钱的凭据）

一条命令，生成一份可以直接发给付费方的报告：

```bash
python3 .claude/skills/lx-goal/scripts/lx-goal.py report --format client --out 交付报告.md
```

它和你自己看的那份**不是同一个版本**：客户版会自动去掉所有内部术语，只留七节——

| 节 | 内容 |
|---|---|
| 一、结论 | 建议验收 / 建议暂缓验收 + 数量表 |
| 二、本次交付内容 | 每条交付项 + 状态 + 验证情况（显示你计划里的标题，不是 S1/S2） |
| 三、这些内容是怎么验证的 | 先测试后实现、操作受约束、全过程可追溯 |
| 四、**需要你决定的事** | 事项 / 为什么需要你定 / 我的建议 + 依据 |
| 五、本次未做的部分 | 范围排除项 + 原因 |
| 六、需要管理员权限执行的操作 | 需要客户自己跑的东西 |
| 七、验收方式 | 怎么逐项验收 |

**怎么用它谈钱**：客户不需要"相信你很厉害"，他只需要**审一份记录**。
第四节尤其关键——它显示你不是"闷头做完才告诉他出了什么问题"，而是**提前把需要他拍板的事摆出来**。

## 9. 出问题了怎么办

| 你遇到 | 原因 | 怎么办 |
|---|---|---|
| `status` 显示 No active task | 它查的是"续跑指针"，不是 goal 状态 | 用 `lx-goal.py status` 查目标状态（见 §5.2） |
| 提示任务已过期 | 超过 6 小时且没有推进 | 重新发起，或发起时给更长时间 |
| 机器重启了 / 换了会话 | 状态都在磁盘，没丢 | `python3 .claude/scripts/carros_base.py resume .omc/tasks/<日期>/<任务名>` |
| 想中止当前目标 | —— | `lx-goal.py off`（会先做检查再关闭，并生成报告） |
| 想让它再试一次 | —— | `lx-goal.py retry` |
| 觉得它快要跑偏了 | —— | 直接打断，改目标范围，重新澄清 |
| 合并分支时冲突 | 你主分支在它干活期间也改了同一处 | 冲突时它会**停下来交给你裁决**，不会硬合；自己解决后再让它继续 |
| 想彻底重来 | —— | 归档旧任务（`lx-goal.py done`），重新发起一个新目标 |

## 10. L1 还是 L2：不用你选，但知道区别有用

它根据「难度 / 危险程度 / 改动面」自己判断，你不用记参数。区别在：

| | L1（简易） | L2（完备） |
|---|---|---|
| 适合 | 单模块、改动小、可逆 | 跨模块、不可逆、碰安全或权限、改动面大 |
| 独立分支隔离 | 不开 | **开** |
| TDD 双门 | 不做 | 执行前依赖测试全绿、特性测试全红；完成时全绿 |
| 双法官验收 | 不做 | 可选（高风险建议做） |
| 你被打扰的程度 | 几乎为零 | 同样为零，但报告里"需要你决定"的项会更多 |

**它判不准时会问你**：给你两条路线 + 推荐项，你选一个就行。

---

## 11. 它不做什么

- **不判断业务对不对**。它管得住 AI 的行为（改哪、能不能改、有没有证据），管不住"这个功能设计合不合理"。业务正确性靠测试和你的验收。
- **不保证零事故**。它是"少翻车 + 留可审计记录"，不是"消灭风险"。
- **不提升模型智商**。不会让弱模型变强，只让任何模型更守规矩。
- **不支持 Windows 原生**（依赖文件锁）。WSL / macOS / Linux 可用。
- **不会偷偷改你的东西**。装的时候只加 `.claude/`、`.omc/` 和两行 `.gitignore`。
